Upscaling de imagens 4x com 4 modelos ESRGAN

Servidor de super-resolution baseado em Spandrel, com API HTTP estilo inemaimg e uma UI web para testar e comparar modelos lado a lado.

Começar o guia Ver no GitHub
O que é

Um servidor dedicado de super-resolution

Projeto irmão do inemaimg, separado para não travar a GPU compartilhada durante batches grandes (na casa de milhões de fotos). Spandrel carrega qualquer .pth ESRGAN-family e expõe tudo numa API HTTP simples.

🔍 4 modelos prontos

4x-UltraSharp (default, foto realista), RealESRGAN_x4plus (JPEG degradado), 4x_NMKD-Siax_200k (comprimida) e 4x_foolhardy_Remacri (nitidez agressiva). Todos 4x.

🔍 API estilo inemaimg

JSON com base64 na entrada e na saída. Um lock asyncio serializa a GPU para que chamadas concorrentes enfileirem em vez de causar OOM.

🔍 UI web para comparar

Playground em http://localhost:8002: arrastar / colar imagem, escolher um modelo ou rodar todos lado a lado, com tempo, download e lightbox.

Como funciona

Da imagem ao 4x em poucos segundos

Você envia a imagem em base64, o Spandrel carrega o modelo escolhido (lazy, cacheado em VRAM), faz tiling interno para caber e devolve o PNG ampliado.

Imagem base64→ POST /upscale→ Lock asyncio (GPU)→ Spandrel + tiling→ 4x→ PNG base64

Carregamento lazy

O modelo só carrega na primeira chamada e fica cacheado em VRAM para as próximas — sem custo de partida repetido.

Tiling interno

tile=512, pad=16 permite inputs de até 4096px de lado sem estourar a memória da GPU.

Saída sempre PNG

O output é PNG para não acumular compressão JPEG entre passes.

Pré-requisitos

O que você precisa antes de subir

Docker com runtime NVIDIA e GPU compatível. A imagem base é a mesma do inemaimg (NGC PyTorch 26.03 arm64-sbsa, Blackwell sm_120, CUDA 13).

Docker + runtime NVIDIA

Compose isolado, lock próprio, porta 8002, cap de memória 8g.

# verifica GPU no Docker
docker run --rm --gpus all nvidia/cuda nvidia-smi

Pesos dos modelos

Script idempotente baixa os 4 .pth do OpenModelDB (~256 MB total).

# baixa os pesos
./models/download.sh

jq (opcional)

Útil para inspecionar as respostas JSON da API.

# debian/ubuntu
sudo apt-get install -y jq
Guia de uso · passo a passo

Subindo e chamando o inemaupsk

Clone, baixe os pesos, suba o compose e já dá para fazer upscale via curl, Python ou pela UI web.

1

Clonar e baixar os pesos

O download.sh é idempotente — pode rodar de novo sem baixar duas vezes.

git clone https://github.com/inematds/inemaupsk ~/projetos/inemaupsk
cd ~/projetos/inemaupsk
./models/download.sh  # ~256 MB, 4 pesos
2

Subir o servidor

Builda a imagem e sobe o container na porta 8002.

docker compose up -d --build
3

Verificar a saúde

Confirma os modelos disponíveis e o default.

curl -s http://localhost:8002/health | jq
# {"status":"ok","available":[...4 models...],"default":"4x-UltraSharp.pth"}
4

Upscale de uma imagem (curl)

Envia o base64, escolhe o modelo e salva o PNG ampliado.

curl -sS -X POST http://localhost:8002/upscale \
  -H 'Content-Type: application/json' \
  -d "{\"image\":\"$(base64 -w0 foto.jpg)\",\"model\":\"RealESRGAN_x4plus\"}" \
  | jq -r .image | base64 -d > foto_4x.png
5

Comparar todos os modelos

/upscale_all roda os 4 em sequência sob o lock — bom para escolher o melhor para cada foto.

curl -sS -X POST http://localhost:8002/upscale_all \
  -H 'Content-Type: application/json' \
  -d "{\"image\":\"$(base64 -w0 foto.jpg)\"}" \
  | jq '.results[] | {model, elapsed_s, output_size}'
6

Usar a UI web

Playground minimalista: arrastar / colar a imagem, alternar entre "um modelo" e "todos (comparar)" e baixar.

# abra no navegador
http://localhost:8002
Exemplos

Casos de uso

A mesma API serve scripts, notebooks e fluxos de automação.

Cliente Python

Leia o arquivo, codifique em base64, faça POST /upscale e escreva o PNG decodificado — pronto para usar em qualquer pipeline.

n8n / agentes

HTTP Request node fazendo POST /upscale com a imagem em base64; o retorno em image segue para o próximo step que aceita base64.

Comparação lado a lado

Use /upscale_all para gerar as 4 saídas de uma vez e escolher visualmente o modelo certo por tipo de foto.

Latência observada (DGX Spark / GB10)

256×256 → 1024×1024 em ~0,85 s; 867×600 → 3468×2400 em ~4,5 s. /upscale_all é cerca de 4x isso.
